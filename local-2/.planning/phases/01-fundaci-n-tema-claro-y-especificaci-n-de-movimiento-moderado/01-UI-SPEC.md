# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase nature:** This is the foundational token/motion phase for the `v1.0-corporate` milestone pivot (dark/cinematic Dogstudio → light/celeste Fugro+Seequent-inspired corporate). It does **not** touch section content or layout (that begins Phase 3). Its two deliverables:
1. A complete **light-mode WCAG AA color token layer** (THEME-01, THEME-02, THEME-03) that replaces every dark-theme literal/blend-mode/filter in `app/globals.css`.
2. A literal, numeric **"moderate motion" spec** (THEME-04) that every later phase's `useGSAP()` call must reference instead of re-deriving its own timing.

No CONTEXT.md exists for this phase. The design decisions below were derived from PROJECT.md's client brief, REQUIREMENTS.md's THEME-01–04 text, and `.planning/research/SUMMARY.md`/`PITFALLS.md`, plus explicit design judgment calls documented with rationale (see "Discretion Calls" at the end of this document) — flag these for user confirmation before Phase 5 (brand content) if any need to change.

## Spacing Scale

The existing codebase uses ad hoc `rem`/`clamp()`/viewport-relative spacing per section, not a fixed 8-point scale — this is a pre-existing editorial-layout convention and **Phase 1 does not modify any section's existing spacing** (no section markup changes this phase).

However, because this is the foundational token phase and Phase 3–5 will introduce genuinely new components (service drawer, equipment carousel, cards) that need a spacing contract, the following 8-point scale is **hereby established as the standard for all new components introduced from Phase 2 onward**. Phase 1 itself does not consume it (no new UI in this phase) but declares it so later phases don't each invent their own:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge padding |
| sm | 8px | Compact element spacing (chip/tag padding) |
| md | 16px | Default element spacing (card internal padding, form field gaps) |
| lg | 24px | Card grid gutters, drawer internal section spacing |
| xl | 32px | Component-to-component spacing within a section |
| 2xl | 48px | Sub-section breaks |
| 3xl | 64px | Page-level section breaks (new components only — existing `.section-pad`'s `clamp(7rem,12vw,13rem)` remains untouched for existing sections) |

Exceptions: existing sections keep their current `clamp()`-based spacing verbatim until their own phase (3, 4, or 5) reworks them; this scale does not retroactively apply to `app/globals.css` in Phase 1.

## Color

### Token Layer (new — replaces all dark-theme tokens)

New semantic tokens, named to avoid any collision with the retired dark tokens (`--ink`, `--paper`, `--orange`, `--hot`, `--dark-line`, `--light-line` — see Retirement Checklist below) so a grep for the old names returns zero hits once migrated (THEME-03 gate):

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant surface (60%) | `--bg-surface` | `#FFFFFF` | Page background default, contact section, brightest content zones |
| Secondary surface (30%) | `--bg-surface-alt` | `#EEF1F4` | "Gris arriba" bands — hero/first-fold, alternating content sections, cards |
| Tertiary surface | `--bg-surface-deep` | `#E3E8ED` | Footer band, secondary nav states, alternate-band anchor (never a full-viewport dark section) |
| Primary text/ink | `--ink-primary` | `#1C2530` | Headings, body copy, primary UI text — a deepened variant of the client's own brochure "azul grafito" (`#2B3141`, see `PALETA-DE-MARCA.md`), tuned darker for max legibility on white while staying in the client's real brand hue family |
| Secondary/muted text | `--ink-secondary` | `#4A5568` | Captions, metadata, muted labels, placeholder text |
| Accent (10%) | `--accent` | `#0B6E8F` | See "Accent reserved for" below — the SINGLE restrained celeste/steel-blue accent required by THEME-01 |
| Accent hover/active | `--accent-hover` | `#0A5A78` | Hover/pressed state of accent-colored controls only |
| Accent tint (decorative only, never for text) | `--accent-soft` | `#E4F0F4` | Badge/tag backgrounds, subtle highlight fills — never used to carry text needing contrast guarantees |
| Destructive/error | `--destructive` | `#B3261E` | Form validation error text/borders only (no delete/destructive actions exist on this marketing site) |
| Border, decorative | `--border-subtle` | `#DCE2E8` | Non-essential dividers where the boundary isn't the sole indicator of a UI component (WCAG 1.4.11 does not apply) |
| Border, functional | `--border-strong` | `#7C899A` | Input field borders, card outlines that ARE the sole indicator of the component boundary — must and does pass 3:1 |
| Focus ring | `--focus-ring` | `var(--accent)` (`#0B6E8F`) | All `:focus-visible` outlines, site-wide |

### Contrast Verification (WCAG AA gate — THEME-02)

Computed via the WCAG relative-luminance formula against the token values above (this is the "chequeo de contraste" the roadmap's Phase 1 success criterion #2 requires; re-verify with WebAIM/axe once implemented since this is a manual pre-computation):

| Pair | Ratio | Required | Result |
|------|-------|----------|--------|
| `--ink-primary` on `--bg-surface` | 15.48:1 | 4.5:1 (normal text) | PASS |
| `--ink-primary` on `--bg-surface-alt` | 13.66:1 | 4.5:1 | PASS |
| `--ink-primary` on `--bg-surface-deep` | 12.56:1 | 4.5:1 | PASS |
| `--ink-secondary` on `--bg-surface` | 7.53:1 | 4.5:1 | PASS |
| `--ink-secondary` on `--bg-surface-alt` | 6.64:1 | 4.5:1 | PASS |
| `--accent` on `--bg-surface` (text/link) | 5.77:1 | 4.5:1 | PASS |
| `--accent` on `--bg-surface-alt` | 5.09:1 | 4.5:1 | PASS |
| `--accent` on `--bg-surface-deep` | 4.68:1 | 4.5:1 | PASS (narrow — do not darken `--bg-surface-deep` further without re-checking) |
| White text on `--accent` button fill | 5.77:1 | 4.5:1 | PASS |
| `--destructive` on `--bg-surface` | 6.53:1 | 4.5:1 | PASS |
| `--destructive` on `--bg-surface-alt` | 5.76:1 | 4.5:1 | PASS |
| `--border-strong` on `--bg-surface` | 3.56:1 | 3:1 (UI component boundary) | PASS |
| `--focus-ring` (`--accent`) on any declared surface | ≥4.68:1 | 3:1 (focus indicator) | PASS |

No token pairing in this system falls below its required threshold. `--accent` on `--bg-surface-deep` is the tightest margin (4.68:1 vs. 4.5:1 required) — flag to executor/checker: do not introduce a darker `--bg-surface-deep` variant without re-running this check.

**Accent reserved for (explicit list — THEME-01's "un solo acento restringido"):** primary CTA/submit button fill, link hover/active underline+color, focus-visible ring (site-wide), active/selected nav item indicator, active carousel dot (Phase 4), selected service-drawer trigger state (Phase 3), form input focus border, key metric numerals (e.g. "4 geólogos", "X proyectos" — sparingly, not every number). **Never** used for: large background fills, decorative shapes/blobs, illustrative icon fills across the page, marketing-copy body text color.

### "Gris arriba, blanco abajo" pattern (client-requested, Seequent+Fugro combination)

This is a **top-to-bottom surface trend across the page**, not a rule applied identically to every section. Recommended section-surface sequence (informational for Phase 3–5 planning — Phase 1 delivers only the tokens, not their per-section application, since no section markup changes this phase):

Hero (`--bg-surface-alt`, gray) → Manifesto/Statement (`--bg-surface`, white) → Capabilities (`--bg-surface-alt`, gray) → Technology (`--bg-surface`, white) → Process (`--bg-surface-alt`, gray) → Contact (`--bg-surface`, white — brightest, for the conversion moment) → Footer (`--bg-surface-deep`, deepest gray-blue, as a light-mode visual "close" rather than a dark band).

This satisfies "gris arriba, blanco abajo" as the overall trend (gray-dominant near the top, white-dominant near the bottom) while alternating for scannable rhythm in between, matching Seequent's light-gray banding + Fugro's clean-white sections without copying either site's exact structure.

### Legacy Dark-Theme Token Retirement Checklist (THEME-03 audit — for planner/executor)

Every one of these must be removed/replaced with the new token layer above. Grep confirms 14 raw literal/blend/filter hits remain in `app/globals.css` as of this writing:

| Legacy token/pattern | Current value | Disposition |
|---|---|---|
| `--ink` | `#0c0e12` (was dark surface + on-light text) | Retire. Do not reuse the name — replaced by `--ink-primary` (text-only role now) and `--bg-surface-deep`/`--bg-surface-alt` (surface roles) |
| `--soft` | `#14171d` | Retire — no longer a dark secondary surface anywhere |
| `--paper` | `#eeeae3` (warm cream) | Retire — replaced by cool-toned `--bg-surface-alt` (`#EEF1F4`); the new direction is celeste/cool, not warm cream |
| `--orange` / `--hot` | `#e46d4b` / `#ff7852` | Retire — replaced entirely by `--accent`/`--accent-hover`. See "Discretion Calls" for why blue, not the brochure orange, was chosen as the single accent |
| `--dark-line` / `--light-line` | `rgba(12,14,18,.18)` / `rgba(255,255,255,.18)` | Retire — replaced by `--border-subtle`/`--border-strong` |
| `mix-blend-mode: difference` | `.site-header`, `.frame-coordinates` | Remove. In a light theme this trick breaks (produces incorrect colors against light backgrounds). Header must render with a solid tokenized background from the outset — Phase 4 (HEAD-01) adds the scroll-reactive toggle on top of this already-solid baseline, it does not introduce the solid background itself |
| `backdrop-filter: blur(10px)` | `.environment-badge` | Remove or replace with a flat `--bg-surface-deep` fill — blur-glass is an atmosphere effect tied to the dark/cinematic direction |
| `filter: saturate(.62) contrast(1.18) brightness(.58)` and siblings | `.hero-media img/video`, `.tech-media img`, `.statement-visual img`, `.deliverable-image img` | Remove the darkening/desaturating treatment entirely (these exist solely to make photography read moody/dark). Real photography should render at natural color under the light theme — do not substitute a different filter stack, use none unless a later phase's UI-SPEC specifies otherwise |
| `.hero-noise` (SVG turbulence grain overlay) | — | Remove — atmospheric grain effect, explicitly the kind of "exceso de efectos" the brief vetoes |
| Various `#ffffffXX`/`#0c0e12XX` alpha literals (gradients, shadows) | multiple | Each is a candidate dark-theme literal — do not mechanically find/replace; re-evaluate per Pitfall 1 whether the effect is still needed at all under the light theme, and if so, re-derive from the new token layer |

**Motion-adjacent, flagged but not mandated for removal in Phase 1** (these belong to whichever phase reworks that section's content — Phase 3 for capabilities, later phases for hero — but must comply with the Motion Contract below if retained): `.hero-orbit`/`orbit-one`/`orbit-two` (continuously spinning decorative rings with `box-shadow` glow) and `.moving-band` (infinite marquee). Continuous, user-uncontrollable looping animation is inconsistent with "moderate" motion — if kept, must become finite/triggered rather than infinite-loop; if removed, that's also compliant.

## Motion & Interaction Contract (THEME-04 — primary deliverable of this phase)

This is the literal, numeric "moderate motion" spec every section's `useGSAP()` call must reference from Phase 2 onward, replacing the prior milestone's "cinematic" intensity. Values are deliberately reduced from the archived Phase 1's cinematic tokens (`lerp: 0.07`, translate 44px, duration up to 1.2s) per THEME-04 and Pitfall 3.

### Scroll Engine (Lenis + GSAP — reused unchanged architecture, retuned values)

| Setting | Cinematic (retired) | Moderate (locked this phase) |
|---|---|---|
| Lenis `lerp` (normal) | `0.07` (heavy/viscous) | **`0.1`** (Lenis's own documented moderate default — snappier, less "floaty") |
| Lenis `lerp` (`prefers-reduced-motion`) | `0.15` | **`0.15`** (unchanged — already the correct "snappier still" delta, kept) |
| `syncTouch` | `true` | `true` (unchanged) |
| Single ticker wiring | `gsap.ticker.add((t) => lenis.raf(t * 1000))` | unchanged — no second `requestAnimationFrame`/scroll listener is introduced anywhere this milestone (avoids the Anti-Pattern this project has already been burned by) |

### Reveal Animation Constants (locked — new CSS custom properties)

| Token | Value | Replaces | Usage |
|---|---|---|---|
| `--motion-distance-max` | `24px` | old `translateY(44px)` on `[data-reveal]` | Max translate distance for any scroll-triggered reveal (fade+slide-in) |
| `--motion-distance-min` | `12px` | — (new) | Subtle/secondary reveals (staggered list items, card grids) |
| `--motion-duration-fast` | `200ms` | `0.3–0.35s` hover states | Hover/focus micro-interactions (button hover, link underline) |
| `--motion-duration-base` | `450ms` (range 400–600ms) | `0.55–0.9s` | Standard section-reveal fade/slide — the default for most `[data-reveal]`-equivalent elements |
| `--motion-duration-slow` | `650ms` (hard cap `700ms`) | `1.15–1.2s` | Largest compound reveals only (e.g. hero heading) — **never exceeds 700ms**, down from the old 1.2s |
| `--motion-stagger-max` | `60ms` between siblings | `70–80ms` (unbounded count) | Cap applies to at most the first 6 siblings in any staggered group; remaining siblings reveal with the 6th's delay (no runaway waterfall on longer lists like the 5 service cards or 4 team members) |
| `--ease-moderate` | `cubic-bezier(0.33, 1, 0.68, 1)` | `cubic-bezier(.16,1,.3,1)` / `cubic-bezier(.76,0,.24,1)` | Single standard ease-out-cubic curve for all new reveals — calmer/more neutral than the old dual sharp/expo curve pair. When consumed by GSAP timelines, register via `CustomEase.create()` or approximate with `power2.out` |

### Explicitly Banned (THEME-04 hard constraints)

- **No `ScrollTrigger.create({ pin: true })` or any pinned/scroll-jacked section** — zero exceptions this milestone (stronger than the archived spec's "at most one short hero moment" allowance; the client brief explicitly asked for "Moderado," not even a single cinematic pin moment).
- **No `scrub`-driven continuous timelines.** Any scroll-linked visual change (e.g. the Phase 4 sticky header) must be a discrete threshold toggle (`ScrollTrigger.create({ toggleClass })`), never a continuously-interpolated scrub.
- **No parallax beyond ±8px translate.** The existing `--parallax` custom-property pattern on `.hero-media`/`.tech-media` may remain only if its range is capped to ±8px (down from the current unclamped viewport-relative drift) — if a later phase can't make it read as "moderate" at that cap, remove it rather than exceed the cap.
- **No `mix-blend-mode`, no `backdrop-filter`, no darkening/desaturating `filter()` stacks** — see Retirement Checklist above (this is the THEME-03 half of the same constraint).
- **No infinite/uncontrolled looping decorative animation** (spinning orbit rings, infinite marquee) unless converted to a bounded, triggered, or user-controlled interaction.

### Reduced-Motion Contract (carried over unchanged from the archived Phase 1 spec — still correct under "moderate")

When `prefers-reduced-motion: reduce` is active, motion is **softened, not switched off**:
- Lenis stays instantiated at `lerp: 0.15` (snappier, not disabled).
- GSAP timelines still play, but duration scales to ~50% of the moderate values above (e.g. `--motion-duration-base` 450ms → ~225ms) and translate distances scale to ~25–35% (e.g. `--motion-distance-max` 24px → ~6–8px).
- Easing simplifies to non-elastic curves (e.g. `power1.out`).
- This branch is established once in `lib/motion-preferences.ts`'s `gsap.matchMedia()` scaffolding and reused by every later phase — not reinvented per section.

### Header, Drawer, Carousel — motion guidance for later phases (informational, locked here so Phase 3/4 don't re-derive it)

- **Sticky header (Phase 4, HEAD-01):** background/shadow toggle at a single scroll threshold via `ScrollTrigger.create({ toggleClass })` — no continuous opacity/size interpolation per scroll pixel (this is explicitly the kind of motion the brief's "Moderado" vetoes as too busy for a technical/corporate site).
- **Service drawer (Phase 3):** open/close transition uses `--motion-duration-base`/`--ease-moderate` — a clean slide-in from the side, not a mask-reveal or clip-path cinematic wipe (retire that pattern from `.menu-overlay`'s current clip-path approach if reused for the drawer; the menu overlay itself is unchanged this phase).
- **Equipment carousel (Phase 4):** any custom slide transition (beyond Embla's own drag/gesture handling) must be driven through the existing GSAP ticker, using `--motion-duration-fast`/`--ease-moderate` — no auto-advance by default (per EQUIP-01), so this is primarily relevant to manual next/prev transitions.

## Discretion Calls (flag for user confirmation before Phase 5 content locks in)

No interactive channel was available to pause mid-research for these; each was resolved with documented rationale so the phase isn't blocked. Revisit before content/branding decisions in Phase 5 finalize if any need to change:

1. **Single accent = celeste-blue (`#0B6E8F`), not the client brochure's orange (`#D26B4C` in `PALETA-DE-MARCA.md`).** THEME-01's requirement text literally specifies "paleta clara/**celeste**"; all 8 client-supplied reference sites (Fugro, WSP, SLR, Hexagon, Trimble Geospatial, Seequent, Tetra Tech, DroneDeploy) are blue/teal/gray-dominant, none use orange as a primary accent; and "SkyTech" itself carries a sky/blue association. `--ink-primary` still honors the client's real brand hue family (deepened from their brochure's azul grafito `#2B3141`). **Recommend confirming logo/accent color usage with the client before Phase 5** in case their actual logo mandates the orange be present somewhere (e.g., as a logo-only mark, not a UI accent).
2. **`PALETA-DE-MARCA.md` is superseded by this document's Color section.** That file was extracted from the client's brochure PDF for the now-deleted `lib/v4-template.ts` dark-theme mechanism (ARCH-03 in the prior milestone removed that file) and never matched what was actually implemented in `app/globals.css` even under the old theme. Recommend a documentation follow-up (outside this phase's execution scope) to update or retire `PALETA-DE-MARCA.md` once this UI-SPEC is approved.
3. **Footer uses `--bg-surface-deep` (light gray-blue), not a dark band**, even though Fugro's own footer is dark. This directly satisfies the roadmap's literal Phase 1 success criterion #1 ("no queda ningún fondo oscuro… de la dirección Dogstudio anterior") — interpreted as zero dark backgrounds anywhere on the site, not just removal of leftover Dogstudio-specific ones.
4. **Orbit rings and marquee band are flagged, not removed, in Phase 1.** Removing/redesigning them touches section markup owned by later phases (capabilities/hero content, Phase 3+); Phase 1 only establishes that if retained, they must stop looping infinitely/uncontrolled.
5. **8-point spacing scale is newly declared for future components** (drawer, carousel, cards) even though no THEME requirement mandates it and Phase 1 doesn't consume it — done so Phase 3/4 don't each invent their own ad hoc spacing.
