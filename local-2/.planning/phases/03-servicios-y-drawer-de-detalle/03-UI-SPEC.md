# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase nature:** This phase adds the first genuinely new interactive component of the `v1.0-corporate` milestone: a native `<dialog>` service-detail side drawer, triggered from the existing 5-eje services list built in Phase 1 (light-theme restyle) and populated with real content in Phase 2 (`lib/site-content.ts`'s `Service.groups`/`note`). It does **not** redefine color, motion timing, spacing scale, or typography weights — all of those are locked in `01-UI-SPEC.md` and are only *applied* here, never re-derived. Five open design questions specific to this phase (row-list vs. card-grid, drawer visual treatment, drawer content structure, trigger cursor copy, mutual-exclusivity visual treatment) were resolved directly with the user on 2026-07-19 — see "Decisions Confirmed" at the end of this document.

## Typography

Reused verbatim from Phase 1's locked 2-weight system (500 for kicker/headings, 400 for body — no third weight introduced). **Consolidated to exactly 4 sizes this phase** (down from an initial 7-size draft that the checker correctly BLOCKed) by merging every label/eyebrow-style role into one shared size, and every secondary-body role into one shared size:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label/eyebrow style — **shared by**: drawer eyebrow (service number), group heading, footer CTA | 0.68rem (≈11px) | 500 | 1.4–1.5, uppercase where noted below — reuses existing `.mono-label`/`.section-kicker` rule verbatim, no new CSS declaration needed |
| Drawer title (service name) | `clamp(1.6rem, 2.4vw, 2.2rem)` (≈26–35px) | 500 | 1.05 — deliberately smaller than `.service-title`'s `clamp(1.45rem,2.8vw,2.7rem)` since the drawer panel is narrower than a full-width row |
| Drawer tagline | 0.95rem (≈15px) | 400 | 1.7 — matches existing secondary-copy convention (`.statement-aside p`) |
| Body copy — **shared by**: bullet item text, note callout (ejes 1 and 5 only) | 0.85rem (≈14px) | 400 | 1.6 |

**Per-role treatment within the shared label size (0.68rem):**
- Drawer eyebrow: no uppercase transform (matches `.mono-label` as-is)
- Group heading: uppercase, `letter-spacing:.1em` (matches `.tech-specs span`/`.file-types span`)
- Footer CTA ("Cotizar este servicio"): uppercase, `letter-spacing:.1em`, line-height 1

**Flag for executor:** the existing `.submit-button` (contact form) uses `font-weight:700`, which predates and falls outside Phase 1's 2-weight consolidation (contact form was explicitly out of scope for the Phase 1 retheme). The new drawer CTA is a **new** component introduced under the now-locked 2-weight contract — it must use weight **500**, not 700, even though it will sit visually near the site's one other CTA archetype. Do not copy `.submit-button`'s weight; do reuse its `--accent` fill / `#FFFFFF` text / hover-to-`--accent-hover` color behavior.

## Color

Reused verbatim from Phase 1's locked token layer (`app/globals.css` `:root`) — no new tokens introduced.

| Role | Value | Usage in this phase |
|------|-------|----------------------|
| Dominant (60%) | `--bg-surface` `#FFFFFF` | Drawer panel background (deliberately white, not `--accent`-filled like `.menu-overlay`, so the drawer reads as "detail panel," not "navigation takeover") |
| Secondary (30%) | `--bg-surface-alt` `#EEF1F4` | Note-callout background (ejes 1/5 only); this is also the existing `.capabilities` section background the trigger rows already sit on, so the drawer's one "tinted" surface stays in the same family as its trigger context |
| Accent (10%) | `--accent` `#0B6E8F` | See "Accent reserved for" below |
| Accent hover/active | `--accent-hover` `#0A5A78` | Hover/pressed state of the drawer's footer CTA button only |
| Destructive | `--destructive` `#B3261E` | Not used this phase — no destructive actions exist in the drawer (read-only content + one navigational CTA) |
| Border, subtle | `--border-subtle` `#DCE2E8` | Divider rule between drawer header and body; divider between groups (thin rule, decorative, not the sole boundary indicator) |
| Focus ring | `--focus-ring` (`var(--accent)`) | `:focus-visible` outline on the drawer's close button, footer CTA, and the service-row/card triggers themselves (see Motion & Interaction Contract) |

**Accent reserved for (this phase's additions to Phase 1's site-wide list — same token, same discipline, no new hue introduced):**
- Drawer footer CTA ("Cotizar este servicio") button fill
- Drawer close-button hover/focus state (text color shift, matching `.menu-toggle`'s existing hover language)
- `:focus-visible` ring on every new focusable element this phase introduces (service-row/card trigger, drawer close button, drawer CTA)
- The already-open trigger row's persistent "selected" indicator while its drawer is open — this exact usage was pre-reserved in Phase 1's accent list ("selected service-drawer trigger state (Phase 3)") and is now specified concretely below (Component Inventory)

**Never** used for: drawer panel background (stays white per the "detail panel, not takeover" decision), note-callout background (uses `--bg-surface-alt`, not accent), group-heading text color (stays `--ink-secondary`-family, not accent — accent is reserved for interactive/selected states only, not static labels).

## Component Inventory & Interaction States

This section is additive to the base template — included because this phase introduces the milestone's first genuinely new component, and the planner/executor need an explicit states contract, not just tokens.

**Visual focal point:** On drawer open, the primary visual anchor is the **drawer title** (service name, `clamp(1.6rem,2.4vw,2.2rem)`, weight 500) — it's the largest text in the panel and sits directly below the smaller eyebrow label, drawing the eye first per standard type-hierarchy scanning order. The scrim backdrop and `inert`-dimmed background reinforce this by removing competing focal points from the rest of the page while the drawer is open.

### Service row/card trigger (`components/sections/capabilities-section.tsx`, existing element, behavior change only)

Per the confirmed decision, the existing `.service-row` markup/layout is **kept exactly as-is** (number, title, tagline, `<Arrow />`) — no restructuring into a multi-column card grid. Only its interaction contract changes:

| State | Visual treatment |
|-------|-------------------|
| Default | Unchanged from Phase 1/2 (existing `.service-row` styles) |
| Hover | Unchanged — existing accent-fill sweep (`.service-row:before{transform:scaleY(1)}` on hover), white text |
| Focus-visible (new — element becomes a `<button>`, not an `<a href="#contacto">`) | `outline: 2px solid var(--focus-ring); outline-offset: -2px` (inset, since the row spans full container width) |
| Selected (its drawer is currently open) | Persistent `--accent` left-edge indicator (reuse the existing `:before` accent-fill treatment, but pinned open rather than hover-triggered) — this is the concrete implementation of Phase 1's pre-reserved "selected service-drawer trigger state" |
| Disabled (menu overlay is open) | `opacity: .6; cursor: not-allowed; pointer-events: none` (reuses `.submit-button:disabled`'s exact visual convention) + `aria-disabled="true"` |

**Cursor/icon:** `data-cursor="Ver detalle"` (was `"Cotizar"`). The `<Arrow />` glyph (↗) is kept unchanged and remains `aria-hidden` — no visual change to it, since the row's overall shape and meaning ("there is more here, go explore it") is preserved even though the destination changed from an anchor scroll to a drawer.

### Service Drawer (`components/service-drawer.tsx`, new)

Native `<dialog>`, opened via `showModal()` / closed via `close()`.

| Region | Content | Notes |
|--------|---------|-------|
| Header | Service number (mono-label) + title + tagline + close control | Close control top-right, `.menu-toggle`-style text+icon ("Cerrar") |
| Body | For each `service.groups[]` entry: optional `heading` (uppercase label) + bulleted `items[]`; `24px` (lg token) gap between groups | Reuses the exact spacing token Phase 1 pre-reserved for this purpose |
| Note callout | `service.note` (present only on ejes 1 and 5) | `--bg-surface-alt` background box, not styled as a warning/error — it's supplementary framing copy, not a caution |
| Footer | "Cotizar este servicio" button, `--accent` fill, closes drawer + scrolls to `#contacto` | Weight 500 (see Typography flag above) |

**Sizing/position (confirmed):**
- Desktop (>1000px): right-aligned panel, `clamp(420px, 44vw, 560px)` wide, full viewport height
- Tablet (721–1000px): right-aligned panel, `70vw` wide
- Mobile (≤720px): full-width (`100vw`), matching `.menu-overlay`'s existing full-bleed mobile treatment
- Backdrop: dialog's native `::backdrop` pseudo-element, styled `background: color-mix(in srgb, var(--ink-primary) 45%, transparent)` — no separate backdrop `<div>` needed, this is the idiomatic native-`<dialog>` mechanism
- Background scroll: locked via the existing shared `useScrollLock` hook (Phase 2), same as `MenuOverlay` — no new scroll-lock mechanism

**Focus & accessibility contract (SERV-02, per PITFALLS.md Pitfall 4):**
- `showModal()` provides native top-layer modality; in addition, apply `inert` to the page's main content wrapper while the drawer is open, as explicit belt-and-suspenders documentation of the requirement's literal "inert en el fondo" wording
- On open: focus moves to the drawer's close button (deterministic first focusable target — the panel has no form fields, so there is no more natural "first control")
- On close (Esc, backdrop click, or close button): focus returns to the exact row/card `<button>` that triggered the open — never to `<body>`
- `aria-labelledby` on the `<dialog>` points to the visible service-title element inside it

**Native `<dialog>` top-layer + custom cursor interaction (resolves the open technical risk flagged in STATE.md Blockers):** `showModal()` promotes the dialog into the browser's top layer, which renders above *all* regular-stacking-context content — including `.custom-cursor` (`z-index:900`, not itself top-layer-promoted). **Design decision: this is accepted, not worked around.** While the drawer is open, the custom animated cursor dot will not render over the drawer panel; the OS-default pointer remains fully functional for all clicks inside it. Do **not** add `data-cursor` to any element inside `ServiceDrawer` (it would be inert/invisible there regardless), and do not attempt to re-parent or z-index-hack `CustomCursor` into the top layer — rely on standard `:hover`/`:focus-visible` states inside the drawer instead (already specified above for the close button and CTA).

### Mutual exclusivity (SERV-03)

Per the confirmed decision: **disable, don't auto-close.** When the drawer is open, `.menu-toggle` (hamburger) gets the same disabled treatment as the service-row trigger table above (`opacity:.6`, `pointer-events:none`, `aria-disabled="true"`). When the menu overlay is open, every service-row trigger gets that same treatment. Neither overlay force-closes the other — the user must close whichever is open before the other becomes available again. This is a read-only, one-directional signal (per `ARCHITECTURE.md` Pattern B) — no cross-component state reach-through.

## Motion & Interaction Contract

No new timing values — this phase consumes Phase 1's locked "moderate motion" spec verbatim (`--motion-duration-base`/`--motion-duration-fast`/`--ease-moderate`), per Phase 1's own explicit pre-guidance for this component ("Service drawer (Phase 3): open/close transition uses `--motion-duration-base`/`--ease-moderate` — a clean slide-in from the side, not a mask-reveal or clip-path cinematic wipe").

| Interaction | Timing | Notes |
|---|---|---|
| Drawer panel slide-in (`translateX(100%) → translateX(0)`) | `var(--motion-duration-base)` (450ms), `var(--ease-moderate)` | Reverse on close |
| Backdrop (`::backdrop`) fade | `var(--motion-duration-fast)` (200ms), linear/opacity only | Runs concurrently with the panel slide, not sequenced before/after it |
| Disabled-trigger opacity change (mutual exclusivity) | `var(--motion-duration-fast)` (200ms) | Matches existing `.service-row`/`.submit-button` transition conventions already in `globals.css` |
| Selected-trigger accent indicator (persists while its drawer is open) | No transition beyond the existing hover-fill transition already declared on `.service-row:before` | Reuses, does not duplicate, existing CSS |
| Reduced motion (`prefers-reduced-motion: reduce`) | Instant show/hide, no slide, no backdrop fade | Per Phase 1's Reduced-Motion Contract (durations → ~50%, but for this binary open/close interaction the correct application is instant, matching Phase 1's own explicit instruction for the drawer: "instant show/hide instead of slide" |

**Explicitly banned (inherited from Phase 1, not re-derived, re-stated here for the executor building the first instance of this pattern):** no `scrub`-driven drawer animation, no pinning, no `mix-blend-mode`/`backdrop-filter` on the panel or backdrop (the native `::backdrop` uses a flat `color-mix()` fill only, not a blur).

## Decisions Confirmed (user, 2026-07-19)

1. **Row-list layout kept as-is (not restructured to a card grid).** The existing `.service-row` list already satisfies "no texto corrido" — each row is a discrete, fully-clickable unit with title/tagline/affordance. Only the click behavior changes (drawer instead of anchor-scroll).
2. **Drawer visual treatment:** right-aligned panel, `clamp(420px,44vw,560px)` desktop / full-width mobile, white `--bg-surface` background, dimmed scrim backdrop, `inert` on background, slide-in using the locked `--motion-duration-base`/`--ease-moderate` tokens.
3. **Drawer content structure:** header (number+title+tagline) → body (grouped bullets, 24px gaps) → note callout (ejes 1/5 only) → footer CTA ("Cotizar este servicio", accent-filled, closes drawer + scrolls to `#contacto`).
4. **Cursor label:** `data-cursor` changed from `"Cotizar"` to `"Ver detalle"` on service rows.
5. **Mutual exclusivity (SERV-03):** reuse the existing `.submit-button:disabled` convention (reduced opacity, `pointer-events:none`, `aria-disabled`) on whichever trigger is inactive while the other overlay is open — no auto-closing.
