Implement a module-scope store holding `{ menu: boolean, drawer: boolean }` with a `Set<() => void>` of listeners, a `setOverlay(key, open)` mutator that no-ops when unchanged and otherwise replaces the state object and notifies listeners, a `subscribe(listener)` returning an unsubscribe, and a `getSnapshot()` returning the current state reference. Export TWO hooks, both reading via React 19's built-in `useSyncExternalStore`:
    (1) `useOverlayCoordination(key: OverlayKey, isOpen: boolean): boolean` — subscribes to the snapshot, runs a `useEffect` keyed on `[key, isOpen]` that calls `setOverlay(key, isOpen)` and returns a cleanup calling `setOverlay(key, false)`, and returns the OTHER key's boolean (`key === "menu" ? snapshot.drawer : snapshot.menu`). This is the read+write coordinator for MenuOverlay and CapabilitiesSection.
    (2) `useOverlayOpen(key: OverlayKey): boolean` — read-only selector: subscribes to the snapshot and returns `snapshot[key]` with NO `setOverlay` effect (so subscribers like InertBoundary can read `"drawer"` without clobbering store state). This is required by Plan 03's inert boundary — do not omit it.
    Type `OverlayKey = "menu" | "drawer"`. Do NOT introduce React Context, a body attribute, or a MutationObserver — the store IS the single source of truth (per Pattern 3, chosen over ARCHITECTURE.md's body-attribute suggestion). This satisfies SERV-03's coordination substrate.

    Create `components/service-drawer.tsx` (`"use client"`) exporting `ServiceDrawer({ service, isOpen, onClose }: { service: Service | null; isOpen: boolean; onClose: () => void })`. Render the `<dialog ref={dialogRef} className="service-drawer">` UNCONDITIONALLY (never `{isOpen && ...}`) so the top-layer machinery survives across close animations (per Pattern 2). Drive it imperatively: a `useEffect` keyed on `[isOpen]` calls `dialogRef.current.showModal()` only when `isOpen && !dialog.open` — NEVER bind a JSX `open={isOpen}` prop (that silently defeats backdrop/focus-trap/Esc — SERV-02 would look done but fail). Call `useScrollLock(isOpen)`.
    Define `const CLOSE_ANIMATION_MS = 450` with a comment that it must stay in sync with `--motion-duration-base` in globals.css. Implement one `requestClose()` used by ALL close paths: it inline-checks `window.matchMedia("(prefers-reduced-motion: reduce)").matches` (this codebase's convention — no new shared util per Current State finding); if reduced, call `.close()` immediately; else set an `isClosing` state (adds `is-closing` class → CSS slide-out) and call the real `dialogRef.current.close()` inside a `setTimeout(CLOSE_ANIMATION_MS)` stored in a ref that is cleared on unmount.
    Wire on the `<dialog>`: `onCancel` → `event.preventDefault()` then `requestClose()` (so Esc animates instead of jump-cutting); `onClick` → if `event.target === dialogRef.current` call `requestClose()` (backdrop click); `onClose` (native, fires after real `.close()`) → reset `isClosing` to false then call `onClose()` prop.
    Panel structure per UI-SPEC: `<header className="service-drawer-header">` with `<span className="mono-label">{service.number}</span>`, `<h2 id="service-drawer-title">{service.title}</h2>`, `<p>{service.tagline}</p>`, and a `<button type="button" autoFocus className="service-drawer-close" onClick={requestClose}><span>Cerrar</span></button>` (autoFocus makes the close button the deterministic first focus target per SERV-02). Set `aria-labelledby="service-drawer-title"` on the dialog. Body: `<div className="service-drawer-body" data-lenis-prevent>` mapping `service.groups` to a group div (optional `service-drawer-group-heading` paragraph + `<ul>` of items), then `service.note` (when present) as `<p className="service-drawer-note">`. Footer: `<button type="button" className="service-drawer-cta" onClick={handleCtaClick}>Cotizar este servicio</button>`.
    `handleCtaClick`: call `requestClose()`, then schedule `lenis?.scrollTo("#contacto")` on `window.setTimeout(..., reduced ? 0 : CLOSE_ANIMATION_MS)` using `useLenis()` (per Pitfall 2 — NOT a plain anchor; the scroll must fire after the close animation and after useScrollLock re-runs `lenis.start()`). Do NOT add `data-cursor` to any element inside the drawer (top-layer renders above the custom cursor — accepted per UI-SPEC).
  </action>
