## Directory Purposes

**app/:**
- Purpose: Next.js app directory containing pages, layouts, and API routes
- Contains: Server components (page, layout), route handlers, global styles
- Key files: `page.tsx` (main narrative), `layout.tsx` (root HTML), `globals.css` (styling)

**app/api/:**
- Purpose: API endpoints
- Contains: Route handlers for external requests
- Key files: `contact/route.ts` (form submission handler)

**components/:**
- Purpose: Reusable React components
- Contains: Client components with interactivity
- Key files: `experience.tsx` (menu, scroll, animations, form submission)

**lib/:**
- Purpose: Utility functions, schemas, and client factories
- Contains: Zod schemas, database clients, helper functions
- Key files: `contact-schema.ts` (form validation), `supabase-admin.ts` (DB connection)

**public/:**
- Purpose: Static assets served directly (images, videos)
- Contains: Images in `IMAGENES_PAGINA_WEB/`, videos in `video/`
- Key files: Hero background video, section images (dron.png, topografia-con-drones.jpg, etc.)

**supabase/:**
- Purpose: Database schema and migrations
- Contains: SQL migration files for creating tables and indexes
- Key files: Schema files in `migrations/`

**scripts/:**
- Purpose: Build-time and deploy-time scripts
- Contains: Utility scripts for CI/CD
- Key files: `block-vercel-deploy.mjs` (prevents accidental Vercel deployments)

**.planning/codebase/:**
- Purpose: Codebase analysis documents
- Contains: Architecture, structure, conventions, testing, concerns maps
- Key files: This directory (generated by GSD codebase mapper)

## Naming Conventions

**Files:**
- React components: PascalCase, single word or multi-word (e.g., `Experience`, `FormConnector`)
- CSS: kebab-case classes (e.g., `.service-row`, `.hero-title`)
- Utilities/functions: camelCase (e.g., `createSupabaseAdmin`, `submitForm`)
- Migration files: Supabase standard (timestamp + name)

**Directories:**
- Lowercase, plural for collections (`components/`, `public/`, `lib/`)
- Nested paths follow feature/domain (e.g., `app/api/contact/`)

**Type Names:**
- TypeScript types and interfaces: PascalCase (e.g., `ContactInput`)
- Zod schemas: camelCase variable (e.g., `contactSchema`)

**Data Attributes:**
- HTML data attributes use camelCase with hyphens: `data-reveal`, `data-parallax`, `data-cursor`, `data-count`
- IDs use kebab-case: `#hero-video`, `#submit-button`, `#contact-form`, `#form-status`

## Where to Add New Code

**New Feature (Page Section):**
- Primary content: Add JSX markup to `app/page.tsx` (import any new images to public)
- Styling: Add CSS rules to `app/globals.css` (follow existing variable/animation patterns)
- Interactivity: If needed, extend `components/experience.tsx` with new event listeners/state
- Assets: Place images in `public/IMAGENES_PAGINA_WEB/`, video in `public/video/`

**New Component/Module:**
- Implementation: Create new file in `components/` (client components only currently)
- Server utilities: Add to `lib/` (e.g., database queries, external API calls)
- Styling: Keep in `app/globals.css` or add scoped CSS in component file if needed

**Utilities:**
- Form-related: `lib/contact-schema.ts` (for validation rules)
- Database: `lib/supabase-admin.ts` (for connection; create separate query files as needed)
- Shared helpers: Create new file in `lib/` with camelCase name

**API Routes:**
- New endpoint: Create `app/api/{feature}/route.ts` following POST handler pattern in `app/api/contact/route.ts`
- Pattern: Parse JSON → validate with schema → perform operation → return NextResponse

## Special Directories

**supabase/migrations/:**
- Purpose: Version-controlled database schema changes
- Generated: Yes (by Supabase CLI when you run migrations)
- Committed: Yes (migrations should be committed to git)
- How to add: Run `supabase migration new <name>` then edit the SQL file

**supabase/.temp/:**
- Purpose: Temporary state for local Supabase instance
- Generated: Yes (auto-generated during `supabase start`)
- Committed: No (.gitignored)

**public/:**
- Purpose: Static assets served directly by CDN
- Generated: No (manually added)
- Committed: Yes (but consider using external storage for large files)

**.next/:**
- Purpose: Build output directory
- Generated: Yes (output of `npm run build`)
- Committed: No (.gitignored)

**Legacy Files (NOT IN USE):**
- `components/v4-interactions.tsx` — Old interaction handler for static HTML template
- `lib/v4-template.ts` — Template loader for landing-page-v4.html
- `landing-page-v4.html` — Static HTML template from previous version
- **Action:** These should be removed as they are dead code. The page is now built with React/Next.js, not static HTML.

## Import Patterns

**Path alias:** `@/*` resolves to project root (`./`)
- ✅ `import { Experience } from "@/components/experience"`
- ✅ `import { contactSchema } from "@/lib/contact-schema"`
- ✅ `import { createSupabaseAdmin } from "@/lib/supabase-admin"`

**External packages:**
- React: `import { useState, useEffect } from "react"`
- Next.js: `import Image from "next/image"`, `import { NextResponse } from "next/server"`
- Supabase: `import { createClient } from "@supabase/supabase-js"`
- Zod: `import { z } from "zod"`
